## S2 Launch Catalogue & Developer Supersession — 2026-08-11

S2 adds one durable `development_supersessions` authority. It records an
explicit, privileged equivalence between a platform-curated source development
and a separate developer-owned replacement; it never transfers custody or
rewrites leads. `verified → active` is cut over in one caller-owned ACID
transaction using the existing S1 publication/readiness primitives: source A
is retired, replacement B is published, the relationship becomes active, and A
retains its immutable normalized root path for a dynamic 308 redirect. The S1
public-eligibility policy independently excludes active supersession sources,
so a restored publication flag cannot make A canonical-public. Reversal keeps
the relationship and historical route, does not republish A or alter B, and
requires a later normal S1 publication decision for any restoration.

Verified replacements are blocked from ordinary publication with
`SUPERSESSION_ACTIVATION_REQUIRED`; active sources are blocked until explicit
reversal. The legacy `convertToSubscriber` custody mutation and its admin
caller now fail closed; separate catalogue creation and explicit S2
verification are required.

## S3 Development Discovery Convergence — 2026-08-12

Public development discovery now has one read authority: the canonical
development service projections. `/new-developments` continues to use
`listPublicDevelopments`; Listing Wizard autocomplete uses
`searchPublicDevelopments`. Both compose the S1 public-development eligibility
policy, including canonical `unitTypes` inventory and S2 active-source
supersession exclusion. Autocomplete also returns the S2-owned current route
identity. No schema or persistence change was required.
