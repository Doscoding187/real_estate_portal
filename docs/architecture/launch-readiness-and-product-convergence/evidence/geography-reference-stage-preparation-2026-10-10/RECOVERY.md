# Reference-stage recovery and custody

This packet authorizes observation/preparation only. Future live recovery uses the admitted exact runner/operation and existing protected authority. The senior owns incident decisions through Edward. Custodian alarms only notify/log; keep active/unknown critical work intact beyond expiry if needed and record the lifetime/cost deviation. Preserve ingress/cron/application/payment holds in every state below.

| Trigger / outcome | Custodian and senior response |
| --- | --- |
| Missing approval, fresh window/custody/alarm, privilege, real connectivity, preservation proof or 60-second exact-binding evidence | Refuse dispatch. Preserve cause. A newly admitted runner is eligible for cleanup only after independently verified idle/closed state and the accepted gate. No production repair, grant, firewall widening or new connection path. |
| Source, `0111`, ledger, congruency, 39 CHECKs, manifest/package/desired/held/plan or assertion drift | Stop and retain the fresh read-only refusal/plan for senior review. Do not delete/adopt rows, clear licensing holds, remap identities or repeat migrations. |
| Transport interruption, missing report, process/SSH exit, missing COMMIT acknowledgement, timer expiry or loss of observation | Set state `unknown`; retain exact operation correlation, identities, session/lock/transaction and structured command evidence. Restore only approved read-only observation. Never infer completion or idle from process/provider status or a past snapshot. No signals, deletion, restart, credential revocation, repeat dispatch or retry. |
| `not-started` | Preserve setup/open failure evidence and independently establish that no apply was sent and every opened resource closed. No automatic retry; a corrected dispatch still needs senior review/fresh admission. |
| `not-committed` | The adapter reports no COMMIT attempt and successful rollback where a transaction started. Independently confirm unchanged assertions, no surviving transaction/lock/session and closure. Treat the failed command as stopped; a new apply requires reviewed approval rather than replay. |
| `rollback-uncertain` | No COMMIT was attempted, but rollback acknowledgement failed. Keep operation unknown. Inspect assertions plus actual transaction/session/lock state read-only; do not presume rollback or remove its runner. |
| `commit-uncertain` | COMMIT was attempted without acknowledged success. No rollback/replay claim. Independently inspect the exact protected subset and live transaction/session/locks; preserve the structured failure and obtain senior acceptance of the observed outcome. |
| `committed-cleanup-failed` | Data committed but reference-lock cleanup was not confirmed. Preserve committed data; independently resolve lock/session/connection state. Never repeat apply or roll back committed data. |
| `transactionOutcome=committed` with connection-close failure | Committed data with failed command closure is not clean success. Preserve data and resolve actual connection/lock/resource closure independently before cleanup. No replay. |
| Read-only plan/verify returns `not-applicable` with closure failure | Its read phase may have completed; the command is still failed and not terminal evidence. Resolve connection closure before marking idle or cleaning up. |
| Successful apply but verifier mismatch / pending or unexpected rows | Keep schema `0111` and all holds. Return exact failure and fresh plan to the senior. No update/delete/manual backfill or full-national fixture verifier. Any repair requires its separately reviewed canonical recovery contract. |
| Runner deletion/readback unknown | Custody remains active until the exact service/deployment/replicas and pending work establish removal. Preserve evidence; no second runner or blind delete retry. |

For interruption, first establish current provider deployment/instance identity and the source lifecycle state. Then use governed metadata/attempt/lock/session and exact reference reconciliation with authorized read-only credentials. The schema attempt ledger cannot certify reference COMMIT: reference intent, structured transaction outcome and connection/session evidence are distinct records. Do not broaden the approved session observer's fixed queries. The manifest-lock diagnostic observes the migration lock only; reference-lock ownership is separately established as described in the execution checklist.

Keep the accepted frozen backup/recovery evidence. Restoring it would return pre-`0111` schema; it does not authorize restore, overwrite, binding changes or running the old application against transitioned schema. A PITR/new-server recovery requires a separately registered and reviewed South Africa North target. Technical data acceptance never automatically authorizes application deployment or commercial reopening.

On terminal success, export sanitized private evidence and exact subset counts, preserve the 720 Places and all dependent exclusions, close ephemeral credentials/shells, confirm zero pending data/attempts and no active or unknown operation. Refresh cleanup evidence and use the accepted gate plus only the senior's task-runner cleanup scope. Preserve provider removal and measured cost readback. Archive warning/expiry/observer units only after removal is independently confirmed.
